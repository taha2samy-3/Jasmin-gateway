# Verification & Code Quality Rules

1. **Code Execution & Tracing**:
   - Always run or trace code before delivering it.
   - Test edge cases and boundary conditions.
   - Review code quality, design, and adherence to best practices.

2. **Honesty & Transparency**:
   - Explicitly specify what was verified (with concrete proof, command output, or trace logs) and what was NOT verified (or could not be tested in the current environment).
   - Never claim "it works" or make assumptions without verified proof.
